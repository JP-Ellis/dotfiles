* Compatibility
Here are some additional functions/macros that could help you configure Doom:

- ~load!~ for loading external ~*.el~ files relative to this one
- ~use-package!~ for configuring packages
- ~after!~ for running code after a package has loaded
- ~add-load-path!~ for adding directories to the ~load-path~, relative to this
  file. Emacs searches the ~load-path~ when you load packages with ~require~ or
  ~use-package~.
- ~map!~ for binding new keys

To get information about any of these functions/macros, move the cursor over the
highlighted symbol at press ~K~ (non-evil users must press ~C-c c k~). This will
open documentation for it, including demos of how they are used.

You can also try ~gd~ (or ~C-c c d~) to jump to their definition and see how
they are implemented.
* User Configuration
Some variables to identify the user, such as with GPG configuration, email, and
various templates or snippets.
#+begin_src emacs-lisp
(setq user-full-name "{{ username }}"
      user-mail-address "{{ email }}")
#+end_src
** GPG
Explicitly set ~GNUPGHOME~ so subprocesses (git, gpg) always use the correct
keyring regardless of env file loading order. GPG 2.5+ creates ~~/.gnupg~ with
~use-keyboxd~ enabled; without this, any subprocess that inherits a missing
~GNUPGHOME~ falls back to that empty keybox and reports "No secret key".
#+begin_src emacs-lisp
(setenv "GNUPGHOME" (expand-file-name "~/.local/share/gnupg"))
(setq epg-pinentry-mode 'loopback)
#+end_src
* Display
Change the visual appearance of Doom Emacs
** Font
Doom exposes five (optional) variables for controlling fonts in Doom. Here
are the three important ones:

- ~doom-font~
- ~doom-variable-pitch-font~
- ~doom-big-font~ -- used for ~doom-big-font-mode~; use this for presentations
  or streaming.

They all accept either a font-spec, font string ~("Input Mono-12")~, or ~xlfd~
font string. You generally only need the first two.
#+begin_src emacs-lisp
(setq doom-font (font-spec :family "Fira Code" :size 12)
      doom-variable-pitch-font (font-spec :family "Inter" :size 12))
#+end_src
** Theme
There are two ways to load a theme. Both assume the theme is installed and
available. You can either set ~doom-theme~ or manually load a theme with the
~load-theme~ function. This is the default:
#+begin_src emacs-lisp
(setq doom-theme 'doom-ayu-dark)
#+end_src
Tweak the theme slightly
#+begin_src emacs-lisp
(setq doom-ayu-dark-brighter-comments 't)
(setq doom-ayu-dark-brighter-modeline nil)
(setq doom-ayu-dark-comment-bg nil)
#+end_src
** Miscellaneous
This determines the style of line numbers in effect. If set to ~nil~, line
numbers are disabled, and ~t~ shows regular line numbers. For relative line
numbers, set this to ~relative~.
#+begin_src emacs-lisp
(setq display-line-numbers-type 'relative)
#+end_src

** Markdown
Eglot ships no default server for Markdown, so point it at [[https://github.com/rvben/rumdl][rumdl]], which serves
diagnostics and quick-fixes over LSP.

Marksman is the usual alternative here and is the stronger choice for
navigation --- it understands ~[[wiki-links]]~, headings and cross-file
references. Eglot runs only one server per buffer, so the two cannot be
combined; swap the command below if navigation ever matters more than linting.
#+begin_src emacs-lisp
(after! markdown-mode
  (set-eglot-client! '(markdown-mode gfm-mode markdown-ts-mode) '("rumdl" "server")))
#+end_src
Apheleia already defines a ~rumdl~ formatter but deliberately leaves Markdown
unmapped, since conventions vary so widely. Opt in explicitly.
#+begin_src emacs-lisp
(set-formatter! 'rumdl '("rumdl" "fmt" "--stdin" "--stdin-filename" filepath)
  :modes '(markdown-mode gfm-mode markdown-ts-mode))
#+end_src
** Python
Pin [[https://github.com/astral-sh/ty][ty]] as the language server. Eglot already knows about it, but it picks from a
list of alternatives and prompts whenever more than one is installed --- and
Ruff is on ~PATH~ for formatting, which would otherwise make that prompt appear
on every Python buffer. Ruff stays in charge of formatting and linting through
Apheleia; ty only supplies types, completion and navigation.
#+begin_src emacs-lisp
(after! python
  (set-eglot-client! '(python-mode python-ts-mode) '("ty" "server")))
#+end_src

*** Ref
#+begin_src emacs-lisp
(use-package! org-ref

  ;; Make sure Org-ref is loaded after Org
  :after org

  ;; Defer loading to not impact start up
  :defer t

  ;; This initialization bit puts the `orhc-bibtex-cache-file` into `~/.doom/.local/cache/orhc-bibtex-cache
  ;; Not strictly required, but Org-ref will pollute your home directory otherwise, creating the cache file in ~/.orhc-bibtex-cache
  :init
  (let ((cache-dir (file-name-concat doom-profile-cache-dir "org-ref")))
    (unless (file-exists-p cache-dir)
      (make-directory cache-dir t))
    (setq orhc-bibtex-cache-file (file-name-concat cache-dir "orhc-bibtex-cache"))))
#+end_src

** Treemacs
Enable git integration within Treemacs. The ~+treemacs-git-mode~ has the following options:
- ~simple~ The files are highlighted based on their git status
- ~extended~ Files and directories are highlighted (requires Python)
- ~deferred~ Same as ~extended~, but asynchronous
#+begin_src emacs-lisp
(setq +treemacs-git-mode 'deferred)
#+end_src

** Astro
Doom has no Astro module. ~astro-ts-mode~ needs the ~astro~, ~tsx~ and ~css~
grammars; Doom already ships recipes for the latter two, but not for Astro
itself, so register it. Without a recipe the mode has no way to install the
grammar and silently falls back to ~fundamental-mode~. The first visit to an
~.astro~ file will offer to build all three.
#+begin_src emacs-lisp
(set-tree-sitter! nil 'astro-ts-mode
  '((astro :url "https://github.com/virchau13/tree-sitter-astro")))

(use-package! astro-ts-mode
  :mode "\\.astro\\'"
  :config
  (set-eglot-client! 'astro-ts-mode '("astro-ls" "--stdio"))
  (add-hook 'astro-ts-mode-local-vars-hook #'lsp! 'append))
#+end_src
** Svelte
The ~web~ module maps ~.svelte~ to ~web-mode~, which treats the file as plain
HTML and loses the script and style blocks. That mapping is registered lazily,
after this file has been read, so claiming the extension here would simply be
overwritten --- reassign it once startup has settled.
#+begin_src emacs-lisp
(use-package! svelte-mode
  :config
  (set-eglot-client! 'svelte-mode '("svelteserver" "--stdio"))
  (add-hook 'svelte-mode-local-vars-hook #'lsp! 'append))

(add-hook! 'doom-after-init-hook
  (defun +svelte-claim-extension-h ()
    (setf (alist-get "\\.svelte\\'" auto-mode-alist nil nil #'equal)
          'svelte-mode)))
#+end_src
