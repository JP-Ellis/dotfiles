# The repository profile

`<common>/tracking-sync/profile.md` records what one repository tracks and
where. Every section is present. A section the repository has nothing for says
`none`, and the matching stream is skipped.

## Format

The values below are invented. Discover each repository's own.

```markdown
# tracking-sync profile

## Forge
forgejo, via `fj`.           <!-- or: github, via `gh` / none -->

## Default branch
main

## Tracking issues
- Root: #12, the ordered roadmap over the epics.
- Epics: open issues labelled `epic`.
- Catch-all: #40, the parent for issues no epic owns.

## Local records
- PLAN.md: a roadmap. Finished items are deleted.
- notes/release-checklist.md: a running checklist. Correct what landed work
  falsifies.

## Read-only inputs
- reports/coverage-history.md, generated by CI.

## Nested repositories
- tools/importer: default branch `main`, no remote.

## Docs
- Roots: README.md, docs/, every AGENTS.md.
- Historical artefacts: CHANGELOG.md, docs/adr/.

## Private material
- PLAN.md and everything under notes/ are ignored by git and name customers.
  Their text reaches the forge only with customer names replaced by roles.

## Filing gate
default                       <!-- or: the "<rule name>" rule in AGENTS.md -->

## Worktrees
default                       <!-- or: .worktrees/<name> under the repository root -->
```

## Building it on the first run

Discover each section, show the whole profile to the user, and ask the
questions the table marks **Ask**. Write the file when they confirm it. The
profile is the one file this skill writes before Step 4.

Discovery reads ignored and private files freely. The private-material rule
governs what leaves the machine, never what the agent reads locally.

| Section | Discovery |
| --- | --- |
| Forge | `git remote get-url origin`. A github.com URL means `gh`. A host that `fj auth list` names means `fj`. No remote, any other host, or a CLI that is not logged in, means `none`. |
| Default branch | `git symbolic-ref --short refs/remotes/origin/HEAD`, minus `origin/`. Without a remote, the branch the primary worktree sits on. |
| Tracking issues | Build the issue dump now with [forge.md](forge.md); Step 1 reuses it. Epics are open issues labelled `epic`, `tracking` or `roadmap`, or whose body holds three or more task lines that link issues. The root is the issue that links the epics. Instruction files and the agent memory may name the root or the catch-all. **Ask** the user to confirm the root, and whether a catch-all exists. |
| Local records | `find . -maxdepth 1 \( -iname 'ROADMAP*' -o -iname 'TODO*' -o -iname 'PLAN*' \)`, plus ignored prose files at the root: `git ls-files --others --ignored --exclude-standard \| grep -v / \| grep -i '\.md$'`. **Ask** which of them are tracking records and how each is maintained. |
| Read-only inputs | **Ask**, offering any generated-looking file from the Local records search. |
| Nested repositories | `find . -type d -name .git -not -path './.git' -not -path '*/node_modules/*' -not -path '*/target/*' -not -path '*/vendor/*'`. A `.git` *directory* is a separate repository; worktrees and submodules have a `.git` file and are skipped. Record each one's default branch and whether it has a remote. |
| Docs | Tracked Markdown: `git ls-files '*.md'`, reduced to roots. Resolve symlinks and list each real file once. Changelogs, ADRs, RFCs and dated specs are historical artefacts. |
| Private material | Every ignored file found above, every nested repository excluded from the parent, and anything an instruction file marks as private or forbids in public text. **Ask** in what form their text may reach the forge. Until answered, the form is "not at all". |
| Filing gate | An instruction-file rule on when deferred work earns an issue. Without one, write `default`. |
| Worktrees | An instruction-file or memory rule on worktree location. Without one, write `default`. |

## Keeping it current

A run that finds the profile wrong proposes the profile edit in Step 4 with the
other file edits. A tracking issue that closed, a local record that was deleted
and a new nested repository are the usual causes.
